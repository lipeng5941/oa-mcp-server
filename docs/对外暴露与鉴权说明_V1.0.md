# 对外暴露与鉴权说明 V1.0

> 适用：`sgs-oa-mcp-server` 2.0.0（统一认证版）
> 状态：**仅本地/内网联调可用；未对外部署，不构成生产可用声明。**
> 本文件对应实施计划 `IMPLEMENTATION_PLAN_V1.0` 的 L1-4（MCP 服务加固）与 L1-4 依赖门。

---

## 1. 一句话结论

服务默认只监听 `127.0.0.1`，身份只认 MaxKey 员工令牌；第三方身份、OA 适配层、对外暴露三件事**都还没批**。
本文写的所有"可用"均指**本机技术链路**，不代表数据可用、第三方可接入或可以上线。

---

## 2. 监听地址（`MCP_BIND_ADDR`）

| 取值 | 行为 | 用途 |
|---|---|---|
| 不设 / 空白 | `127.0.0.1`（默认） | 本机与经 SSH/隧道转发的联调 |
| `127.0.0.1` | 只绑回环网卡 | 同上 |
| `0.0.0.0` | 绑所有网卡，启动时打印警告 | **需要单独的暴露审批**（见 §6 门），未批不得使用 |
| 其它任意值 | 启动即失败（`exit=2`，报 `MCP_BIND_ADDR 只允许 127.0.0.1 / 0.0.0.0`） | 防手误绑错地址 |

实测（本机，2026-11-11）：

- 默认启动 → `netstat` 只有 `TCP 127.0.0.1:<port> LISTENING`；
- `MCP_BIND_ADDR=0.0.0.0` → `TCP 0.0.0.0:<port> LISTENING` 并打印警告；
- `MCP_BIND_ADDR=10.0.0.5` → 配置校验失败，进程退出码 2。

回滚：不设 `MCP_BIND_ADDR` 即回到默认回环；旧版绑 `0.0.0.0` 的行为只能靠显式配置恢复，不会自动回来。

## 3. `/health` 的语义（`dataMode` / `adapter` 字段）

### 3.1 默认（`LEDGER_DATA_MODE=adapter`，实时适配层）

```json
{"status":"ok","version":"2.0.0","authMode":"oidc","dataMode":"adapter","realtime":true,"adapter":"configured"}
```

| 字段 | 取值 | 含义 |
|---|---|---|
| `status` | `ok` | 进程在跑、HTTP 可应答。**与数据是否可取无关** |
| `dataMode` | `adapter` | 台账数据来自 OA 内部适配层（实时） |
| `realtime` | `true` | 每次调用都回源 OA，`fetchedAt` 语义为"服务端当前时间" |
| `adapter` | `configured` | `OA_ADAPTER_URL` 的 host:port **TCP 可连** |
| `adapter` | `unreachable` | 适配层未接入 / 网络不通 / 服务异常（探测 1.5s 超时） |

探测实现：只做 TCP 连接，**不发服务 JWT、不带员工身份、不读上游错误体**；结果缓存 5 秒。
响应里不含适配层 URL、服务 JWT、上游错误内容——只有这两个字面量。

**不要把 `adapter: configured` 当成"数据可用"。** TCP 能连只说明端口开着；真实取数还要过 §6 的 G-7。
反过来 `adapter: unreachable` 时，任何工具调用都会 502，此时 MCP 技术验收可过、数据验收 HOLD。

### 3.2 快照模式（`LEDGER_DATA_MODE=snapshot`，非实时）

```json
{"status":"ok","version":"2.0.0","authMode":"oidc","dataMode":"snapshot","realtime":false,
 "note":"快照数据（本地 data/current.json），非实时 OA；写入/变更不会反映","adapter":null,
 "snapshot":{"available":true,"fetchedAt":"2026-11-11T07:50:21.700Z","rowCount":3387,"version":"fd59a8f397bf","schemaVersion":1}}
```

- `dataMode=snapshot` + `realtime=false` 是硬标：**任何调用方都不得把快照当实时 OA**。快照是 `repair-ledger-data` 某个时间点的落地文件，OA 后续的新增/变更/结清都不会反映。
- `snapshot.fetchedAt` 是**快照抓取时间**（不是服务启动时间）；`snapshot.version` 是文件内容 sha256 前 12 位，用于第三方判断"我拿到的是哪一版数据"；`snapshot.rowCount` 是全量行数（**不是**当前员工可见行数）。
- 不回显快照文件的绝对路径；`snapshot.available=false` 表示文件读不到（此时工具调用报错，不会静默返回空集）。
- 快照模式**不探测也不使用** `OA_ADAPTER_*`：`adapter` 固定为 `null`，服务 JWT 无需配置。

## 4. 身份与鉴权（不得放宽）

- **唯一身份来源**：MaxKey 颁发的员工令牌（`AUTH_MODE=oidc` 走 JWT+JWKS 验签；`AUTH_MODE=oauth2-userinfo` 走 userinfo 校验）。
- 员工编号只从已验证令牌的 claim 取；`X-Employee-No` 请求头、工具入参里的 `employeeNo` 一律忽略。
- 会话与身份绑定：会话创建时的令牌身份即会话身份，换一个员工的令牌复用同一 `Mcp-Session-Id` → `401 令牌身份与会话不匹配`。
- 无令牌访问 `/mcp` → `401` + `WWW-Authenticate: Bearer resource_metadata="..."`。
- `/health` 与其后的 OAuth 元数据（PRM / AS metadata）是唯一无鉴权路径，不含业务数据。
- **禁止**：放宽员工令牌校验、开 `EMPLOYEE_NO_FALLBACK_SUB` 凑合、免鉴权白名单、共享静态 API Key、共享 OA Cookie / WebBridge 会话桥。以上任一项都要重新走安全评审，不属于运维配置项。

审计：`logs/audit.log` 只落员工编号哈希（`employeeNoHash`）+ 事件类型 + 请求 ID，不落明文员工号、令牌、Cookie。

## 5. 数据接口的已知限制（第三方接入前必读）

### 5.1 `actsts=2`（逾期）筛选在上游 500

`search_investment_ledger` 的 `actsts` 只接受 `1`（正常）/`2`（逾期）/`3`（已结清）以内的字典值，其它值 400。
但**按 `actsts=2`（逾期）筛选时上游接口返回 500**，本服务如实透出为 502/上游错误，不做本地兜底、不做静默改写成空结果。

- 第三方不得把 `actsts=2` 当作可用筛选条件写进对接代码或产品文案；
- 需要"逾期"视图时，只能拉全量后在本地按 `actsts` 字段过滤（受 `LEDGER_EXPORT_MAX_ROWS` 上限约束），并在结果里标明是本地过滤；
- 该限制是上游缺陷（source-scout G2），修复前一直有效。

### 5.2 分页/规模边界

- `size` 允许 1~100，`size=101` → `400 INVALID_ARGUMENT`；
- 全量导出受 `LEDGER_EXPORT_MAX_ROWS`（默认 10000）硬上限约束，超过直接拒绝而不是截断；
- 全量导出要求翻到"空页"为止，并核对 `total`；`total` 中途变化、页内记录 ID 完全重复 → 直接报错，不返回混合快照。

### 5.3 49 列口径

`view=display` 与文档表格侧共用 `toLedgerDisplayRow`，`placeholder_199..203` 只是 5 个重复语义列的**输出键占位名**（页面 columns 425~429），取值来自 `sourceField`，不新增字段、不改格式化口径。

### 5.4 快照模式的数据语义（`LEDGER_DATA_MODE=snapshot`）

快照模式不是"另一个适配层"，而是把 `repair-ledger-data` 落地的 `data/current.json` 当只读数据源：

| 维度 | adapter（默认） | snapshot |
|---|---|---|
| 数据来源 | OA 内部适配层实时查询 | `LEDGER_SNAPSHOT_PATH`（默认 `./data/current.json`），只读、不联网 |
| 行级权限 | OA 进程内按员工身份裁剪（`X-Employee-No`） | **ACL 夹具**：`LEDGER_SNAPSHOT_ACL_PATH` 指定的 `{employees:{<员工编号>:[actbasid,...]}}`；未覆盖当前员工 → `403 PERMISSION_DENIED`（fail-closed，绝不退化成全员可见） |
| 身份来源 | 已验证令牌 claim | 同左。**body/入参自报的 `employeeNo` 在两种模式下都忽略** |
| 49 列 display | `toLedgerDisplayRow` | 同一函数、同一 49 列口径 |
| 过滤/分页/排序 | 传上游 SQL | 进程内计算，口径见下 |
| `compcusnm` / `dealdate` | 上游实现 | **显式 `400 INVALID_ARGUMENT`**（快照无对应字段/判定逻辑，不猜口径） |
| 实时性 | 实时 | **非实时**；`_meta.realtime=false` + `_meta.snapshotVersion` |

工具返回体新增 `_meta`：

```json
{"_meta":{"dataMode":"snapshot","realtime":false,"acl":"snapshot-acl-fixture",
          "snapshotVersion":"fd59a8f397bf","snapshotFetchedAt":"2026-11-11T07:50:21.700Z","snapshotRowCount":3387}}
```

快照侧过滤口径（与页面一致的最小集合）：

- 名称类 `projectnm` / `cusnm` / `site`：**包含匹配**（大小写不敏感），对应页面"模糊查询"；
- 编号类 `projectno` / `ctrtcode`：**精确匹配**（`PX-1` 不会命中 `PX-10`）；
- `actsts`：字典值精确匹配；`sort` + `order`：数值列按数值、其余按字符串稳定排序；
- 先按 ACL 裁剪、再过滤 → 筛选条件永远不能扩大可见范围（已用 e2e S3 断言）。

**ACL 夹具的边界**：它只代行"某员工能看到哪些 actbasid"这一件事，用来在内网把权限链路跑通；
行级权限的**业务口径**（按机构 / 经办人 / 项目组）属 G-8 待裁决项，本服务不自行选定。生产语义必须回到 adapter 模式。

由于快照来自同一份页面数据，`view=display` 已与知识库文档 3387 篇 × 49 列逐格核对：
165,963 个单元格中"未解释差异 = 0"（差异仅两类：文档侧 `（页面列，上游本期无值）` 标注 13,548 格、
cell 首尾空白 622 格）。金额缺值统一为 `未披露`，**不再渲染成 `0 元`**。

## 6. 未批的门（HOLD，不是"待办优化"）

| 门 | 内容 | 现状 | 影响 |
|---|---|---|---|
| **G-7** | OA 内部适配层（`OA_ADAPTER_URL` 的真实服务）未连通/未验收 | **HOLD** | 只能报 `adapter: unreachable`，工具调用 502；**adapter 模式**的数据验收（49 列逐字符一致、分页 total）无法成立。`LEDGER_DATA_MODE=snapshot` 可在内网用 `data/current.json` 完成本地数据与权限验收，但**不解除本门**：快照 ≠ 实时适配层 |
| **第三方身份** | 第三方系统以什么身份调 MCP（是否代员工、是否有独立 client、是否需要新的令牌方案）未定 | **HOLD，未批** | 当前只有 MaxKey 员工令牌一条路；不得为此新增静态 Key、不得共享令牌、不得代持他人身份 |
| **对外暴露** | 公网/跨网访问、反向代理、TLS 终结、白名单 | **HOLD，未批** | `MCP_BIND_ADDR` 保持 `127.0.0.1`；不得对外部署 |

上述任一门未批，都不得对外宣称"第三方可调用"或"MCP 可用"。本仓库的 e2e 使用 **mock MaxKey IdP + mock OA 适配层**，`mock ≠ 真实适配层`，e2e 全绿只证明协议与权限逻辑正确。
`test/e2e-snapshot-real.mjs` 额外用**真实快照数据**（3387 行 / 49 列）+ mock MaxKey IdP + 双员工做了内网 HTTP 验收，结论只能写"内网快照链路可用"——**它不是实时 OA，也不构成三方可用**。

## 7. 本地自检命令

```bash
npx tsc --noEmit                       # 类型检查
npm run build                          # 产出 dist/
npm run test:unit                      # 单测（绑定地址 / placeholder / /health 不泄露 / 快照 ACL 与过滤）
npm run test:e2e                       # mock IdP + mock 适配层 + 快照夹具，端到端（25 项）
node test/e2e-snapshot-real.mjs        # 真实快照 data/current.json + mock IdP + 双员工，内网 HTTP（9 项）
curl -s http://127.0.0.1:3000/health   # 看 status / dataMode / realtime / adapter
netstat -ano | grep <port>             # 看实际监听网卡
```

快照模式最小启动（仅内网联调；`data/current.json` 由 repair-ledger-data 产出）：

```bash
export LEDGER_DATA_MODE=snapshot
export LEDGER_SNAPSHOT_PATH=/e/项目/山钢/数智办公/ledger-knowledge-sync/data/current.json
export LEDGER_SNAPSHOT_ACL_PATH=/path/to/acl.json   # 必填；未配置启动即失败（fail-closed）
export MCP_BIND_ADDR=127.0.0.1
node dist/index.js http
```

判断口径：单测、e2e 全绿只能写"本地技术验收通过"；写"字段一致性通过""第三方可用""可上线"都属于越过 §6 的门。
快照模式全绿可加一句"内网快照链路（非实时）验收通过"，**不得**写成"OA 实时数据验收通过"。
