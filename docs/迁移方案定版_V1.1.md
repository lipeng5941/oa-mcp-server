## 一、定版结论

**路线：方案 A（OAuth2/OIDC 授权码 + PKCE）为主，方案 A'（OAuth2 授权码 + userinfo 校验）为降级开关。**

- 代码以 `AUTH_MODE` feature flag 双模并存：`oidc`（方案A，JWT/JWKS 验签）与 `oauth2-userinfo`（方案A'，opaque 令牌 + /sign/api/oauth/v20/me 校验），一键切换，满足回滚要求。
- 若 MaxKey 管理员确认 OIDC 未启用（2026-08-14 实测 OIDC authorize 500），默认以 `oauth2-userinfo` 上线；管理员配置 JWKS 后改 `oidc`。
- MCP 规范（2026-07-28）合规点已全部落地：
  - RFC 9728 Protected Resource Metadata（`/.well-known/oauth-protected-resource`）
  - 401 响应携带 `WWW-Authenticate: Bearer resource_metadata="..."`
  - RFC 8414 授权服务器元数据镜像（`/.well-known/oauth-authorization-server/sign`，因 MaxKey 不对外发布 8414 元数据，网关镜像一份，端点指向实测存活的 MaxKey 端点）
  - PKCE S256 声明；令牌校验（iss/aud/exp/nbf/签名）；会话身份绑定（防会话劫持）

## 二、目标架构（已实现部分 + 待环境部分）

```
AI Agent（Claude Code / Cursor / 内部 Agent）
   │ ① POST /mcp 无令牌 → 401 + WWW-Authenticate
   │ ② GET PRM → 指向 MaxKey
   │ ③ MaxKey authorize（PKCE S256）→ 员工登录（密码只给 MaxKey）
   │ ④ code → token（Agent 侧完成）
   ▼
MCP Server（oa-mcp-test.sgscf.cn，HTTPS）          ← 本次已实现（2.0.0）
   │ ⑤ 校验令牌（方案A: JWKS 验签 / 方案A': userinfo）
   │ ⑥ 提取员工编号 Claim（只信已验证令牌）
   │ ⑦ 服务 JWT + X-Employee-No + X-Request-Id
   ▼
OA 内部适配层（内网）                                ← 待 OA 开发（P4）
   │ ⑧ 员工编号 → OA 用户 → 原权限 Service
   ▼
OA 原有 Service（行级权限）
```
